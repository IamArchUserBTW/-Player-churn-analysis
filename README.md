# Анализ оттока игроков

Учебный ML-проект: прогнозирование оттока игроков мобильной игры. Цель бизнеса: заранее находить игроков, которые скоро перестанут играть, и вмешиваться (снижать сложность или давать бонусную валюту), чтобы повысить LTV игры.

Полное описание проекта (цели, постановка задачи, метрики, план работ) лежит в отчёте `Otchet_Gaming_Churn.docx`.

## Данные

Используется открытый датасет об уровнях, сыгранных пользователями мобильной игры. Он описан в статье Christian Galea «How to Predict Player Churn, with Some Help From ChatGPT» (Towards Data Science, 20.06.2023). Датасет предоставлен игровой компанией, название игры не раскрывается.

- Лицензия: CC BY-SA 4.0 (нужно указывать автора, производные материалы публикуются на тех же условиях).
- Целевая переменная `Churn`: 1, если игрок не играл более двух недель, иначе 0.
- В используемой версии файла (`game_data_level_sql.csv`): 789 879 строк (одна строка равна одному сыгранному уровню), 4 770 игроков, 42 столбца, период 01.01.2019–30.04.2019.
- Отток редкий: Churn = 1 в 0,68% строк.

**Сам CSV-файл в репозиторий не загружаем** (он большой, около 183 МБ). Каждый участник скачивает его сам и кладёт в папку `data/`. Эта папка добавлена в `.gitignore`.

## Установка

Рекомендуется Python 3.9 или новее. Установка всех нужных библиотек одной командой:

```
pip install pandas numpy matplotlib tabulate scikit-learn lightgbm
```

Что для чего нужно:

| Библиотека | Зачем |
|---|---|
| pandas, numpy | работа с таблицами и числами |
| matplotlib | графики в разведочном анализе |
| tabulate | красивые таблицы в отчёте `eda_report.md` |
| scikit-learn | логистическая регрессия, случайный лес, метрики, разбиение данных |
| lightgbm | модель LightGBM (нужна только для `--model lgbm`) |

## Запуск

Положите `game_data_level_sql.csv` в папку `data/` и выполните:

**1. Разведочный анализ**
```
python eda_churn.py data/game_data_level_sql.csv --out eda_output
```
Результат: `eda_output/eda_report.md` (цифры) и графики в формате PNG. Если у CSV другой разделитель, добавьте `--sep ";"`.

**2. Baseline и модели**
```
python baseline.py data/game_data_level_sql.csv --model logreg
python baseline.py data/game_data_level_sql.csv --model rf
python baseline.py data/game_data_level_sql.csv --model lgbm
```
Модели: `logreg` (логистическая регрессия, baseline), `rf` (случайный лес), `lgbm` (LightGBM). Случайный лес на всём файле работает долго.

## Как оцениваем модели

Метрики одинаковые для всех участников и считаются функцией `evaluate()` в `baseline.py`. Менять её можно только по общему согласованию.

- **PR-AUC** (главная метрика): отток редкий, обычная accuracy бесполезна (модель «всегда 0» даёт 99,3%).
- **ROC AUC**: качество ранжирования игроков по риску.
- **Recall, precision, F1 по классу 1** (отток).
- **Log-loss и Brier score**: качество вероятностей.

Разбиение данных идёт по игрокам: один игрок не попадает одновременно в обучающую и тестовую выборки. Порог решения подбирается на валидации, а не на тесте.

## Результаты

Тестовая выборка, разбиение по игрокам, доля оттока в тесте 0,74%.

| Модель | PR-AUC | ROC AUC | Recall | Precision | F1 |
|---|---|---|---|---|---|
| logreg (baseline) | 0,034 | 0,836 | 0,234 | 0,046 | 0,077 |
| rf | 0,026 | 0,770 | 0,147 | 0,027 | 0,045 |
| **lgbm** | **0,048** | **0,849** | 0,178 | 0,068 | 0,099 |

Лучшая по главной метрике: LightGBM. Для сравнения: случайная модель дала бы PR-AUC около 0,0074.

## Что нужно знать об этих данных

- Часть столбцов бесполезна (одно значение во всех строках): `LevelType`, `NextCar`, `AddMoves`, `DoubleMana`, `UsedChangeCar`, `WatchedVideo`, `Platform`. Платформа в данных только Android.
- `Level` и `MaxLevel`, а также `ExtraMoves` и `BuyMoreMoves` полностью коррелируют.
- Метка `Churn` стоит на строке, а не на игроке (у 3 955 игроков она меняется внутри истории).
- Доля оттока по неделям падает до нуля в конце апреля 2019. Вероятно, потому что метка требует двух недель отсутствия. Поэтому разбиение по времени для этих данных рискованно.
- Датасет другого жанра (не хоррор) и без ежедневных заданий, поэтому служит основой для отладки пайплайна.

## Как работаем командой

1. Принять приглашение соавтора (приходит на почту и в уведомления GitHub).
2. В GitHub Desktop: **File → Clone repository** → выбрать этот репозиторий.
3. Для каждого эксперимента создавать свою ветку: **Branch → New branch**, например `lightgbm-experiment`.
4. Сделать изменения, написать описание коммита и нажать **Commit**, затем **Push origin**.
5. Предложить слияние через **Create Pull Request**. Перед слиянием кто-то один из команды смотрит изменения.
6. Перед началом работы подтягивать чужие изменения: **Fetch origin**, затем **Pull**.

CSV-файл и папку `eda_output/` в репозиторий не коммитим.
